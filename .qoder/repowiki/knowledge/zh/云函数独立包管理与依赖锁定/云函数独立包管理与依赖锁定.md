本仓库的依赖管理采用「每个云函数一个独立 npm 包」的模式，位于 cloudfunctions/<function>/package.json，由微信开发者工具在部署时自动安装。

系统/工具
- 包管理器：npm（通过微信开发者工具的「云开发」能力驱动）
- 运行时：Node.js（微信云托管环境）
- 无根级 package.json、pnpm-lock.yaml、yarn.lock 或 go.mod，也不存在 vendor/ 目录

关键文件与模式
- 每个云函数目录均包含独立的 package.json + package-lock.json + node_modules/，形成细粒度依赖边界
- 绝大多数函数仅依赖 wx-server-sdk ~2.6.3（使用波浪号允许补丁更新）
- 少数函数扩展了业务依赖：login 额外引入 bcryptjs ^2.4.3 用于密码哈希；其余如 achievements、aiChat、flashcards、getCourseDetail、getCourseList、home、knowledgeMap、mistakes、pet、quiz、report、settings 等保持最小依赖

架构约定
- 按功能域拆分云函数（认证、首页聚合、课程、AI 答疑、错题、成就、宠物养成、学习报告、设置等），每个函数自管其依赖，避免跨函数共享包
- 未使用 monorepo 工具（no pnpm workspace / lerna / nx），也未将公共库抽离为独立包
- 依赖版本策略：SDK 用 ~（兼容补丁），第三方库用 ^（允许次版本升级）

开发者应遵循的规则
1. 新增云函数时在 cloudfunctions/<name>/ 下创建 package.json，仅声明该函数实际用到的依赖
2. 优先复用已有的 wx-server-sdk ~2.6.3，不要随意升级主版本，以免破坏云函数运行环境兼容性
3. 修改依赖后提交对应的 package-lock.json，确保团队构建可重现
4. 不在 miniprogram/ 前端代码中直接 require 云函数依赖；前后端依赖严格隔离
5. 如需引入新的第三方库，评估是否真的需要——云函数冷启动对包体积敏感，尽量保持轻量
