本仓库采用微信开发者工具 + 微信云开发的全栈架构，配置系统围绕三个层次组织：项目级、小程序端运行时、云函数运行时。

## 1. 使用的框架与工具
- 微信开发者工具：以根目录 project.config.json 作为工程统一入口，声明小程序根路径、云函数根路径、基础库版本、编译选项等。
- 微信云开发（wx-server-sdk）：前端通过 wx.cloud.init 初始化，后端每个云函数在入口文件顶部调用 cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV }) 接入数据库、存储等服务。
- Node.js 18.15 运行时：所有云函数通过各自 config.json 的 runtime 字段指定为 Nodejs18.15。

## 2. 核心配置文件与位置
- 项目级配置：project.config.json — 定义 miniprogramRoot、cloudfunctionRoot、appid、libVersion、setting 编译开关等。
- 小程序应用配置：miniprogram/app.json — 声明页面路由、窗口样式、自定义 tabBar、sitemap 等。
- 小程序运行时配置：miniprogram/app.js 中的 globalData.env 硬编码当前云环境 ID，并在 onLaunch 中调用 wx.cloud.init。
- 云函数配置：每个云函数目录下的 config.json 声明权限、超时、运行时；index.js 顶部统一执行 cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })。

## 3. 架构与约定
- 环境隔离策略：小程序端将云环境 ID 写死在 app.js 的 globalData.env；云函数使用 cloud.DYNAMIC_CURRENT_ENV 自动绑定到部署目标环境，二者配合实现前端指向一个环境、后端随部署环境动态选择的模式。
- 按功能域拆分云函数：cloudfunctions/ 下每个业务模块独立一个云函数目录，拥有自己的 package.json、config.json 和 index.js，便于单独部署与权限控制。
- 登录态持久化：小程序启动时从 wx.getStorageSync('userInfo') 恢复登录态并设置 globalData.isLoggedIn，未登录则拦截跳转至 /pages/login/login。
- 无 .env / 环境变量机制：仓库内未发现 .env、.env.*、application.properties、config.yaml 等外部化配置；敏感值（如云环境 ID）直接硬编码在源码中。

## 4. 开发者应遵循的规则
- 修改云环境时，需同步更新 miniprogram/app.js 中的 globalData.env，否则小程序无法连接到正确的云资源。
- 新增云函数时，复制现有目录结构（config.json + index.js + package.json），保持 cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV }) 不变。
- 不要在云函数中再显式传入 env 字符串，始终使用 cloud.DYNAMIC_CURRENT_ENV，以便通过开发者工具或 CI 切换部署环境。
- 如需引入新的外部服务密钥（第三方 API Key、数据库连接串等），建议集中放入对应云函数的 config.json 或通过云开发的环境变量能力注入，避免散落在业务逻辑中。
- 小程序全局状态仅用于轻量配置（如 isLoggedIn、userInfo），不应承载大量业务数据，以免增大本地缓存体积。
