本仓库未引入任何独立的构建系统（Makefile、Dockerfile、CI 流水线、打包脚本等），而是完全依赖**微信开发者工具 + 微信云开发平台**的原生工作流，形成一种“零脚本、IDE 驱动”的极简构建模式。具体表现如下：

1. **统一入口与配置**：根目录 `project.config.json` 是微信开发者工具的单一项目配置文件，同时声明了小程序前端（`miniprogram/`）与云函数集合（`cloudfunctions/`）两个模块，使 IDE 在打开仓库后自动识别前后端结构。
2. **前端构建**：`miniprogram/` 为原生微信小程序源码（`.js/.wxml/.wxss/.json`），由微信开发者工具在本地直接编译、预览、上传至云端，无需 webpack / rollup / vite 等第三方打包器。
3. **后端构建**：`cloudfunctions/<功能>/` 下每个子目录是一个独立的云函数，包含 `index.js`、`package.json`、`config.json` 以及已预置的 `node_modules/`；云函数由微信开发者工具按目录逐个上传到云开发环境执行，不经过 Node 本地编译或打包步骤。
4. **依赖管理**：云函数侧使用 npm 包管理器（`package.json` + `package-lock.json`），但仅用于声明运行时依赖，构建阶段仍由云开发平台在云端拉取并安装，本地不做 `npm run build` 之类的产物生成。
5. **缺失的 CI/CD 与制品发布**：仓库中不存在 `.github/workflows`、Jenkinsfile、Dockerfile、`build*.sh`、`Makefile` 等自动化构建与发布文件，也没有版本标签或发布流程约定；部署动作通过微信开发者工具手动触发。

**开发者应遵循的规则**：
- 新增页面或组件时，直接在 `miniprogram/pages/` 或 `miniprogram/components/` 下创建对应的 `.js/.wxml/.wxss/.json` 四件套，并在 `app.json` 中注册路由。
- 新增云函数时，在 `cloudfunctions/` 下新建同名目录，提供 `index.js` 作为入口、`package.json` 声明依赖、`config.json` 配置权限，然后使用微信开发者工具右键“上传并部署：云端安装依赖”。
- 不要自行添加 Makefile、Dockerfile 或自定义构建脚本，以免与微信开发者工具的工作流产生冲突。
- 如需跨团队协作，确保所有人使用相同版本的微信开发者工具，并通过共享 `project.config.json` 保持项目配置一致。
