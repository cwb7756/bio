本仓库采用「云函数返回结构化 code/msg + 小程序端 fail 回调静默处理」的错误处理模式，未引入统一的错误类型、中间件或全局异常捕获机制。

## 1. 系统/方法概述
- 云函数层：每个云函数 index.js 的 exports.main 使用 try/catch 包裹业务逻辑，成功时返回 { code: 0, data }，失败时返回 { code: -1, msg }；参数校验通过独立的 validateParams 函数在入口处拦截并返回 { code: 400, msg }。
- 小程序层：调用 wx.cloud.callFunction 后仅在 success 分支检查 res.result.code === 0 判定成功，fail 回调中仅 console.error 并恢复 loading 状态，不弹出用户提示（静默降级）。
- 无全局错误中间件：未定义统一的错误类、错误码枚举或全局 Promise reject 处理器；各云函数各自实现 validateParams 和 catch 块。

## 2. 关键文件与位置
- 云函数入口（统一返回结构）：cloudfunctions/home/index.js、cloudfunctions/login/index.js、cloudfunctions/getCourseList/index.js、cloudfunctions/getCourseDetail/index.js、cloudfunctions/quiz/index.js、cloudfunctions/mistakes/index.js、cloudfunctions/pet/index.js、cloudfunctions/flashcards/index.js、cloudfunctions/knowledgeMap/index.js、cloudfunctions/achievements/index.js、cloudfunctions/aiChat/index.js、cloudfunctions/report/index.js、cloudfunctions/settings/index.js
- 小程序登录态与全局守卫：miniprogram/app.js（checkLogin 跳转登录页）
- 典型页面调用示例：miniprogram/pages/home/home.js（loadHomeData / syncPetCat）

## 3. 架构与约定
- 统一响应体：所有云函数遵循 { code: 0|400|-1, data?, msg? } 格式，前端以 code === 0 作为成功标志。
- 参数校验前置：每个云函数顶部定义 validateParams(obj)，对字符串长度 >10000 与数组长度 >100 进行拦截，返回 { code: 400, msg }。
- 异常兜底：try/catch 内 catch(err) 记录 console.error 后返回 { code: -1, msg: '服务器异常' }；login 云函数额外解析 err.errMsg 中的 duplicate key 给出友好提示。
- 前端静默失败：fail 回调仅打印日志并关闭 loading，不向用户展示错误弹窗；部分场景用 wx.showToast({ icon: 'none', title: '功能开发中...' }) 做占位提示。
- 登录态保护：app.checkLogin() 在未登录时直接 navigateTo('/pages/login/login')，由业务页面在需要鉴权的操作前调用。

## 4. 开发者应遵守的规则
1. 返回值规范：云函数必须返回 { code: 0, data } 成功体；业务错误返回 { code: -1, msg }，参数错误返回 { code: 400, msg }，禁止抛出未捕获异常。
2. 参数校验：新增接口需在 exports.main 开头调用 validateParams(event)，并在返回错误时立即 return。
3. 异常捕获：业务逻辑整体包裹在 try/catch 中，catch 块至少记录 console.error 并返回 -1 错误码；涉及唯一索引等可预知异常时可解析 errMsg 给出更友好的 msg。
4. 前端处理：调用云函数后仅在 success 分支判断 res.result.code === 0；fail 回调只做日志与 UI 恢复，不要弹错框以免干扰用户体验。
5. 鉴权守卫：需要登录态的操作前先调用 getApp().checkLogin()，未登录自动跳转登录页。
6. 避免硬编码错误信息：将用户可见的 msg 从云函数返回，不要在小程序端拼接中文提示，保证多端一致。
